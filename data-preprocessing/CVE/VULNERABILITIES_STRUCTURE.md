# CVE Output Field Reference

Full attribute-by-attribute breakdown of every record in this module's seven
output files. Percentages are "present on this % of that file's own record
count." Generated by walking every record in each file, not sampled.

`x_nvd_cvss` no longer exists as a nested attribute anywhere in this
project's output — it has been fully unnested into four separate entity
files (`cvss_v2_scores.json`, `cvss_v3_scores.json`, `cvss_v4_scores.json`,
`ssvc_assessments.json`), each linked back to its owning CVE by an edge in
`relationships.json`. See `README.md` for the rationale.

## `vulnerabilities.json` (346,947 records)

One record per CVE.

| Field | Type | Present | Description |
|---|---|---|---|
| `id` | string | 100% | The CVE identifier itself, e.g. `"CVE-1999-0001"`. This is the record's join key everywhere in this project's output (`relationships.json`, `external_relationships.json`, and CWE's own `CWE-N --related-to--> CVE-N` edges all reference this value). Format `CVE-\d{4}-\d+`. |
| `stix_id` | string | 100% | The original STIX object id, `vulnerability--<uuid5>`, kept for traceability back to the raw crawled bundle. Not used as a join key anywhere. |
| `type` | string | 100% | STIX object type discriminator. Constant: always `"vulnerability"`. |
| `spec_version` | string | 100% | STIX spec version this object conforms to. Constant: always `"2.1"`. |
| `created` | string | 100% | ISO-8601 timestamp — NVD's `published` date. |
| `modified` | string | 100% | ISO-8601 timestamp — NVD's `lastModified` date. |
| `description` | string | 100% | English-language vulnerability description from NVD. Never empty (min length 15 chars, max 3,998). |
| `x_nvd_vuln_status` | string (enum) | 100% | NVD's workflow status for this CVE. See table below. (`"Rejected"` records are filtered out entirely during preprocessing, so that value never appears here.) |
| `x_nvd_source_identifier` | string | 100% | Identifier of the organization that owns/submitted this CVE record — either an email address (e.g. `"cve@mitre.org"`) or a UUID standing in for an org without a public email. 455 distinct values. |

### `x_nvd_vuln_status` values

| Value | Count | Meaning |
|---|---|---|
| `Modified` | 240,939 (69.4%) | Analyzed at least once, then updated again afterward. |
| `Analyzed` | 64,657 (18.6%) | NVD has completed its analysis and not touched it since. |
| `Deferred` | 39,255 (11.3%) | NVD has decided not to (or not yet) perform its own analysis. |
| `Awaiting Analysis` | 1,507 (0.4%) | Published but still queued for NVD's analysis team. |
| `Received` | 335 (0.1%) | Just ingested from a CNA. |
| `Undergoing Analysis` | 254 (0.1%) | NVD analysis is actively in progress. |

## `cvss_v2_scores.json` (194,545 records)

| Field | Type | Present | Description |

| `impactScore` | float | 100% | 0–10. |

| `obtainUserPrivilege` | bool | 100% | Whether it grants regular user-level privileges. |

| `accessVector` | string (enum) | 100% | `NETWORK` (162,434), `LOCAL` (27,113), `ADJACENT_NETWORK` (4,998). |
| `accessComplexity` | string (enum) | 100% | `LOW` (118,925), `MEDIUM` (69,791), `HIGH` (5,829). |

## `ssvc_assessments.json` (163,361 records)

One record per `ssvcV203[]` entry — CISA's Stakeholder-Specific
Vulnerability Categorization, a decision-tree triage model rather than a
numeric score. The source `ssvcData.id` field (a redundant echo of the
owning CVE's own id) is dropped; `ssvcData.options[]` — a list of
single-key objects, one per decision point — is flattened directly onto
this record. Linked to its CVE by a `has_ssvc_assessment` edge.

| Field | Type | Present | Description |
|---|---|---|---|
| `id` | string | 100% | `ssvc-assessment--<uuid5>`, deterministic. |
| `type` | string | 100% | Constant: `"ssvc-assessment"`. |
| `source` | string | 100% | Org id of the assessor. 8 distinct values, overwhelmingly one CISA uuid (`134c704f-...`, 163,215 of 163,361 entries). |
| `role` | string (enum) | 100% | `CISA Coordinator` (163,337), `CNA` (23), `Coordinator` (1) — the capacity in which the assessor is scoring this CVE. |
| `version` | string | 100% | Constant `"2.0.3"`. |
| `timestamp` | string | 100.0% (163,337/163,361) | ISO-8601 timestamp of when this SSVC assessment was made. |
| `exploitation` | string (enum) | 100% | `none` (123,367), `poc` (38,352), `active` (1,642) — evidence of exploitation seen in the wild. |
| `automatable` | string (enum) | 100% | `no` (126,130), `yes` (37,231) — whether the exploit steps can be automated at scale. |
| `technicalImpact` | string (enum) | 100% | `partial` (108,195), `total` (55,166) — degree of control/damage gained on successful exploitation. |

## `external_relationships.json` (323,027 records)

`CVE-N --related-to--> CWE-N` edges, `source_name: "cwe"` throughout — id,

## Fields removed during preprocessing (not present anywhere in this module's output)

For reference — see `README.md` for the full rationale:

- `external_references` — dropped entirely (redundant self-reference plus non-entity bibliography URLs).
- `x_nvd_configurations` (CPE applicability data) — dropped entirely (nested AND/OR boolean tree, no lossless flat edge to extract).
- `name` — dropped from `vulnerabilities.json`; its value now lives in `id` instead.
- Records with `x_nvd_vuln_status == "Rejected"` — dropped outright (empty shells).
- CVSS v4.0's 14 environmental-override fields — dropped (100% `NOT_DEFINED` across this dataset).
- SSVC's `ssvcData.id` — dropped (redundant echo of the owning CVE's own id).
